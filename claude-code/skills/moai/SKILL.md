# MOAI スキル — AIマーケティング司令室の実行エンジン

ブラウザで開いた MOAI（`http://localhost:4173`）に積まれた指示を、Claude Code が実際に実行して結果を返すためのスキル。

> 画面の「▶ AIに実行させる」ボタンからも、このスキルが同じ形で呼び出される（サーバーが `claude -p "/moai"` を起動する）。
> どちらの経路でも手順は同じ。

- ワークスペース: MOAI を置いたフォルダ（以下 `<MOAI>`）
- データ: `<MOAI>/data/*.json`（**必ず** `node <MOAI>/cli.js` 経由で更新する。手編集すると壊れる）
- 画面の起動: `node <MOAI>/server.js`

> 初回に `<MOAI>` の場所を確認し、以後はそのパスを使うこと。

## 起動時にやること（標準フロー）

### 1. 前提を読み込む

```
node <MOAI>/cli.js context
```

ブランドのミッション・トーン・禁止ワード・運用ルール・チャネル一覧・直近KPIが出力される。
**この前提はこのセッション中の全生成物に適用する。** 特に運用ルール（体験の捏造をしない・出典を記録する等）は例外なく守る。

### 2. 指示キューを読む

```
node <MOAI>/cli.js queue
```

`id` / 指示文 / 担当エージェント / 対象チャネル / チャネル固有の前提 が出る。

### 3. 1件ずつ実行する

キューは**古い順**に処理する。

1. `担当` に `agent:xxx` が示されていれば、その名前で Agent ツールを呼ぶ。
   独立した指示が複数溜まっている場合は**まとめて並列起動**してよい（リサーチ系は特に効果が大きい）。
2. `担当` が `skill:xxx` なら、そのスキルを Skill ツールで起動する。
3. `おまかせ` の場合は、指示文と対象チャネルから自分で適切な担当を選ぶ。迷ったら
   `data/agents.json` の `desc` を読んで決める。
4. **外部サイトへの投稿・送信を伴う操作はサブエージェントに任せず、メインスレッドが直列で実行する。**

### 4. 生成物を承認キューに戻す

文章・脚本・記事など「人間が確認してから世に出すもの」は、必ず `status=review` でタスク化する。
本文は一時ファイルに書いてから `--body-file` で渡す（長文をコマンドラインに直接埋めない）。

```
node <MOAI>/cli.js task-add \
  --title "記事：〇〇" \
  --channel ch_blog --agent ag_writer \
  --instruction "元の指示文" \
  --body-file <MOAI>/tmp/out.md \
  --status review
```

分析・調査結果など「読み物」は `report-add` を使う。

```
node <MOAI>/cli.js report-add --title "週次レポート" --kind 週次 --body-file rep.md
```

### 5. 指示を完了にして、報告を残す

```
node <MOAI>/cli.js inbox-done <inboxId> --result "記事1本を承認キューに追加"
node <MOAI>/cli.js msg "記事を1本作成しました。承認キューで確認してください。" --author "戦略ディレクター"
```

### 6. 最後にユーザーへ要約する

処理した件数・作った成果物・承認待ちになったもの・できなかったものを箇条書きで報告する。

## 承認済みタスクの公開

`status=approved` は「人間がOKを出した＝公開してよい」もの。
ユーザーが「承認したものを公開して」と言った場合のみ公開し、公開後に状態を更新する。

```
node <MOAI>/cli.js task-set <taskId> --status published --note "公開しました"
```

**承認されていないタスク（review / queued）を勝手に公開してはいけない。**

## 自律モード（「今週の戦略を立てて」と言われたとき）

キューが空でも、以下を自分で判断して提案する。

1. `cli.js context` で目標と直近KPIを確認する
2. 各チャネルの `cadence` と `data/tasks.json` の履歴を突き合わせ、**投稿が止まっているチャネル**を検出する
3. 目標との差分が大きいチャネルを優先し、今週やるべきタスクを3〜5件 `status=queued` で作成する
4. `msg` で「なぜその優先順位にしたか」を1〜2行で残す

投稿停止は伸び悩みの最大要因なので、必ず最初に見る。

## 実績の記録

```
node <MOAI>/cli.js metric --date 2026-09-06 --ch_instagram 132 --revenueJpy 1500
```

チャネルIDをそのままオプション名に使える。記録するとダッシュボードの推移グラフに反映される。

## 同梱エージェント

`claude-code/agents/*.md` を `~/.claude/agents/` にコピーすると使えるようになる。

| MOAI上の名前 | 実体 |
|---|---|
| 戦略ディレクター | メインスレッド（このスキル自身） |
| SEOリサーチャー | `moai-seo-researcher` |
| コンテンツライター | `moai-content-writer` |
| SNSコピーライター | `moai-social-copywriter` |
| 競合アナリスト | `moai-competitor-analyst` |
| グロース分析官 | `moai-growth-analyst` |
| 収益ファネル設計 | `moai-funnel-designer` |
| 動画・Reels企画 | `moai-video-director` |

自分で作ったサブエージェントやスキルを割り当てたい場合は、MOAIの「AIチーム」画面の
`backend.target` を、そのサブエージェント名／スキル名に書き換える。

## 注意

- `data/` 配下のJSONを直接 Edit / Write しない。必ず `cli.js` を使う（画面が5秒ごとに読み直すため、壊れたJSONは即エラーになる）
- 長文は `<MOAI>/tmp/` に一時ファイルを作ってから `--body-file` で渡す
- 外部への投稿・送信は、ユーザーが承認キューで承認したものに限る
