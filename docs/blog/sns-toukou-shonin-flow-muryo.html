SNS投稿の承認フローを無料で作る方法｜必要な3要素とチェックリスト

公開: 2026-10-02 ・ 更新: 2026-10-02 ・ MOAI 編集部

要点
  • SNS投稿の承認フローとは「作る人」と「出してよいと決める人（または工程）」を分け、未承認のものを公開しない仕組みのこと。商用のSNS管理ツールでは有料プランの機能として提供されることが多い
  • 無料で作るなら、状態（下書き→承認待ち→承認済み→公開済み）と、承認の基準と、差し戻しの記録の3つがあれば成り立つ
  • 1人運用でも承認フローは有効。生成AIを使うなら、事実確認・広告表記・体験談の捏造チェックを承認の関門に置く
  • オープンソースのMOAIは、承認キュー（承認／差し戻し／却下）とタスクの状態管理を無料で提供する。予約投稿・自動公開の機能はなく、公開は人が各SNSで行う

SNSの投稿を誰かに確認してもらってから出したい。生成AIで作った文章を、そのまま出すのは不安。そう考えて「承認フロー」で検索すると、出てくるのは企業向けのSNS管理ツールが中心で、無料で使える選択肢はなかなか見つかりません。

この記事では、SNS投稿の承認フローに必要な要素を分解し、費用をかけずに作る方法を2通り（スプレッドシートで作る方法と、オープンソースのMOAIを使う方法）説明します。あわせて、承認のときに何を確認すればよいかのチェックリストも載せています。

承認フローとは何か

承認フローは、投稿を作る工程と、公開してよいかを判断する工程を分け、判断が済んでいないものは公開しない、という仕組みです。商用のSNS管理ツールでは、たとえばコムニコ マーケティングスイートの公式ページで「1〜3段階の承認フローを設定することができ」「未承認の投稿は予約時間になっても公開されません」と説明されています（コムニコ公式：承認フロー）。

こうした専用ツールの強みは、承認と予約投稿がつながっていて、承認しなければ自動で止まる点です。一方、無料で作る場合は、予約投稿とは切り離し、「承認済みになったものだけを人が投稿する」という運用で同じ目的を果たします。

承認フローに必要な3つの要素

1. 状態

投稿の1本1本が、いまどの段階にあるかが一目で分かること。最低限、次の4つの状態があれば足ります。

状態意味次に動く人
下書き（待機）作成中、または作成を依頼した段階作成者（人またはAI）
承認待ち作成が終わり、判断を待っている承認者
承認済み公開してよいと決まった投稿担当
公開済みSNSに出した（計測へ）

加えて「却下」の状態を持っておくと、出さなかったものと、その理由を後から振り返れます。

2. 承認の基準

「なんとなく良さそう」で承認すると、基準が日によって揺れ、差し戻された側も直し方が分かりません。承認・差し戻し・却下の線引きを、先に文章で決めておきます。

判定基準の例
承認チェックリストをすべて満たし、直しが軽微（数分で済む）
差し戻し方向は合っているが、根拠不足・表現の問題・形式の違いがある
却下ブランドの方針に合わない、事実を確認できない、権利や法令の問題がある

3. 差し戻しの記録

差し戻すときは、どこを、どう直してほしいかを1〜3行で残します。記録が残っていれば、同じ指摘を繰り返さずに済み、AIに作らせている場合は、その指摘を次の依頼文や「禁止事項」に反映できます。

承認のときに確認するチェックリスト

投稿1本ごとに、次の項目を確認します。生成AIで作った投稿は、特に1〜3を重点的に見てください。

  1. 事実：数字・日付・制度・価格に誤りがないか。出典を確認できるか
  2. 体験・実績の捏造：使っていない商品の感想、存在しない顧客の声、実績のない数字が書かれていないか
  3. 広告表記：PR・アフィリエイトを含む場合、広告であることが分かる表示があるか。2023年10月から景品表示法でステルスマーケティングが規制対象になっています（消費者庁）
  4. 効果の表現：「絶対」「必ず」「No.1」のように、根拠を示せない断定がないか
  5. 権利：画像・動画・音源・引用文の権利に問題がないか。人物が写っている場合の許可
  6. トーン：ブランドの言葉づかい、禁止ワードに沿っているか
  7. リンク：URLが正しいか。リンク先が公開されているか
  8. タイミング：災害・事件など、投稿を控えるべき出来事が起きていないか

このリストは、承認する人の手元に毎回置ける場所に保存しておきます。MOAIを使う場合は「設定」の運用ルールに書いておくと、AIへの指示にも毎回引き継がれます。

方法1：スプレッドシートで作る

もっとも手軽なのは、Googleスプレッドシートなどの表計算で管理する方法です。列を次のように作ります。

列内容
ID投稿ごとの番号
SNSX・Instagram・Threadsなど
投稿予定日公開したい日時
本文投稿の文章
状態下書き／承認待ち／承認済み／公開済み／却下（入力規則でプルダウンにする）
差し戻しメモ直してほしい点
承認者・承認日誰がいつ判断したか

利点は、すぐに始められ、共有も簡単なことです。欠点は、AIへの依頼や実績の記録とは別の場所になるため、依頼文・生成物・承認・数字があちこちに散らばりやすいことです。投稿が週に数本で、AIをあまり使わないなら、これで十分です。

方法2：MOAIの承認キューを使う

AIに投稿文を作らせる運用なら、依頼から承認、記録までを1か所にまとめられるMOAIが向いています。MOAIはオープンソース（MITライセンス）の無料ツールで、ブラウザで開くだけで使えます。

MOAIでの承認フローの流れ

  1. 前提を書く：「設定」にミッション・トーン・禁止ワード・運用ルール（上のチェックリスト）を書く
  2. 依頼を積む：「指示する」で、たとえば「承認済みの記事から、Instagram用キャプションを3案」と書き、担当（SNSコピーライター）とチャネルを選ぶ
  3. AIに作らせる：ブラウザ版は「キューをまとめてコピー」でChatGPT・Claudeに貼る。ローカル版は「▶ AIに実行させる」で Claude Code が処理する
  4. 承認キューで判断する：生成物を読み、「承認する」「差し戻し」「却下」のいずれかを押す。差し戻しでは「どこを直してほしいか」を書く欄が出て、その内容が修正の依頼として再びキューに積まれる
  5. 人が投稿する：承認済みの本文を「本文をコピー」で取り出し、各SNSで投稿する。終わったらタスクの状態を「公開済み」にする
  6. 記録する：「チャネル」に実績を記録し、ダッシュボードで推移を見る

タスク画面では、待機→実行中→承認待ち→承認済み→公開済みの状態がカンバンで並び、各タスクの履歴（誰が、いつ、何をしたか、差し戻しのメモ）も残ります。上で挙げた「状態」「基準」「差し戻しの記録」の3要素が、そのまま画面に用意されている形です。

MOAIは承認していない生成物を勝手に公開しません。そもそもSNSへの投稿機能を持たないため、公開は必ず人の手を通ります。ローカル版で Claude Code に自動実行させる場合も、同梱スキルは承認されていないタスクを公開しないルールで動きます。

方法の比較

比較項目スプレッドシートMOAI商用SNS管理ツール

状態管理列で手動管理カンバン・履歴つきあり

複数人の多段階承認と予約投稿の連動が必須なら、商用ツールを選ぶのが確実です。1人〜少人数でAIを使って投稿を作るなら、MOAIで依頼から承認までをまとめるのが手間を減らせます。

SNSごとに承認で見るポイント

共通のチェックリストに加えて、SNSごとに見落としやすい点があります。承認者が迷わないよう、チャネルごとの注意も運用ルールに書いておきます。

SNS承認時に追加で見る点
X文字数の上限内に収まっているか。引用や返信の場合、元の投稿の文脈とずれていないか。リンクを本文に入れるか、返信に回すかの運用ルールに沿っているか
Instagram画像・動画と本文が対応しているか。キャプション内のURLはリンクにならないため、誘導先の書き方（プロフィールのリンクなど）が運用に合っているか。ハッシュタグがブランドと無関係なものになっていないか
Threads会話調の文章が、ブランドのトーンから外れすぎていないか。連続投稿の場合、1投稿目だけ読んでも意味が通るか
YouTube・ショート動画タイトル・概要欄・字幕の内容が動画と一致しているか。音源の利用条件を満たしているか
ブログ出典リンクが生きているか。広告リンクに広告表記があるか。古い情報（料金・制度）が残っていないか

導入の進め方：最初の2週間

  1. 1日目：チェックリストと承認基準（承認・差し戻し・却下の線引き）を文章にする。MOAIなら「設定」の運用ルールに書く
  2. 1週目：投稿の本数を普段より少なめにし、すべてを承認キュー（またはスプレッドシート）経由で出す。承認を経ずに投稿したものがないかを週末に確認する
  3. 2週目：差し戻しと却下の理由を読み返し、同じ理由が2回以上あれば、依頼文の型か運用ルールに反映する
  4. 2週間後：承認に時間がかかりすぎていないかを見直す。たまるなら本数を減らすか、承認の基準を簡素にする

承認フローは「止める仕組み」であると同時に、「次の依頼をよくする材料を集める仕組み」でもあります。差し戻しの記録がたまるほど、AIへの依頼は具体的になり、最初から承認できる投稿が増えていきます。

1人で運用する場合の承認フロー

「承認する人がいないから、承認フローは要らない」と考えがちですが、1人運用でこそ、作る自分と判断する自分を分ける仕組みが効きます。

  • 時間を空ける：作った当日には承認せず、翌日に読み直してから判断する。勢いで書いた表現に気づきやすい
  • チェックリストを声に出して確認する：上の8項目を1つずつ確認する。慣れても省略しない
  • まとめて承認しない：承認キューがたまっても、1本ずつ判断する。たまるなら依頼の本数を減らす
  • 却下の理由を設定に戻す：同じ理由で却下したものは、禁止ワードや運用ルールに追記し、次の依頼から防ぐ

承認を含む運用全体の回し方は、AIマーケティングの運用ループを無料で回す手順で1週間の例とともに説明しています。

よくある質問

Q. MOAIは予約投稿できますか

できません。MOAIはSNSへの投稿機能を持たず、承認済みの本文を人が各SNSで投稿する前提です。予約投稿が必要な場合は、各SNSの公式の予約機能や、予約投稿に対応したツールと併用してください。

Q. 上長やクライアントに承認してもらう使い方はできますか

MOAIは1人1ブラウザ（またはローカル版を1台のPC）で使う前提で、複数アカウントでの承認機能はありません。画面を共有して一緒に確認するか、データを書き出して受け渡す形になります。社外の承認者がいる運用には、チーム機能を持つ商用ツールが向いています。

Q. 差し戻した内容はどうなりますか

差し戻しの欄に書いた修正指示は、タスクの履歴に残り、同時に「修正して再提出」という依頼として実行キューに積まれます。次にAIへ依頼するときに、その指示も一緒に渡ります。

Q. 無料のままずっと使えますか

MOAIはMITライセンスのオープンソースで、ツール自体に費用はかかりません。AIへの依頼に使うChatGPT・Claudeなどの利用料は、各サービスの料金体系に従います。

Q. 承認済みの投稿の数字も記録できますか

できます。「チャネル」画面で日々の実績（フォロワー・PV・収益など）を記録でき、ダッシュボードで推移をグラフで見られます。各SNSから自動で取り込む機能はないため、手入力です。

無料で承認フローを始める

ブラウザ版なら登録もインストールも不要です。「設定」にチェックリストを書き、指示を1つ積んで、承認キューで判断するところまで数分で試せます。

MOAIをブラウザで開く（無料・登録不要）

Claude Code で自動実行したい場合は GitHubリポジトリ からローカル版を入手できます（手順は Claude Codeでマーケティングを自動化するやり方）。
